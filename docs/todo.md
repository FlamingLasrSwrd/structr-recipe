| **Undo a booking** | 2026-11-23: "Are there other processes that should have the options to undo?" (with plan 1's untick, to build) | Every booking's nodes are named by its token, so a booking can be taken back by deleting what that token wrote, **while nothing later rests on it**; after that it stands, and a correction (a Use, a Count) is offered instead, with the reason. Structr's changelog keeps a second record where it is on (it is on the owner's instance: `docker-compose.yml`, `docs/structr-features.md` batch 1, every write with who and when, as files on the `structr-changelog` volume that `tools/backup.py` backs up), but the undo must not depend on it: it adds overhead to every write and grows without end (34 to 36 MB for one full rebuild), so a production or hosted install may turn it off or limit it to some types (`changelogDisabled`).
